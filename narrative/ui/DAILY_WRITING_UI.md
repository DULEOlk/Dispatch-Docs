# 每日撰写 UI 概念记录

更新日期：2026-09-20（Asia/Shanghai）。

本文件记录每日撰写的早期概念图与当前实现边界。用户已确认：撰写目前只有概念，没有实际完成的 UI。概念图用于保留方向，不能当作现成 Widget、正式流程或视觉验收基线。

## 概念证据

![每日撰写流程概念](images/daily-writing-process-concept-2026-08-17.png)

![每日撰写完成状态概念](images/daily-writing-complete-concept-2026-08-17.png)

概念图表达了“从当天经历中选择内容，逐步形成一页记录并封存”的体验：选择日期/状态、核心事件、相关人物、处理矛盾信息、形成结论，最终合上日记。页面还设想用“记录可信度印记”表达记录的完整或可靠程度，并通过纸页、选项纸条、回填文字和盖章形成仪式感。

## 与当前确定规则的关系

- 当前正式玩法方向仍是**每天固定三个撰写部分**，每部分必须有无条件默认项；可用选项由玩家实际获得的线索、推论、委托结果、对话选择或其他事实开放。
- 概念图中的“五步撰写过程”是早期视觉/交互设想，不能直接覆盖“三段撰写”的数据合同。后续可以吸收其“逐步回填、预览全文、封存仪式和可信度反馈”，但步骤数量与字段必须重新设计。
- 当前代码已经有每日撰写模板、条件选项、默认项、提交/取消、当日封存、可信度/立场/结局贡献等底层合同，也有进入/退出 `WritingWidgetClass` 的运行入口；项目中尚无一套已经确认并验收的正式撰写 Widget。
- 可信度不是客观真相评分。它应表达记录在玩家当时知识和选择下的可靠/含混程度，不能直接告诉玩家哪条世界真相是正确答案。

## 后续设计必须回答

1. 三个正式撰写部分如何映射到纸页和逐步选择，而不重新发明一套五步数据；
2. 默认选项如何表现“沉默、敷衍、无法判断或拒绝表态”，而不是空白占位；
3. 选项如何显示来源或开放原因，同时避免把隐藏真相与结局权重直接泄露给玩家；
4. 未提交时怎样返回白天，提交后怎样明确封存、进入睡觉/下一日；
5. 可信度印记是在选择过程中预览、提交后固定，还是只在某些叙事条件下出现。

## 明确不包含

- 不把概念图文字、五步结构、第三日示例或印记档位写入正式 DataAsset。
- 不新建或修改 Writing Widget、撰写系统、DayFlow、结局规则、素材或正式文本。
- 不宣称撰写 UI 已完成；自动化通过的只是底层事务合同，不是玩家体验验收。
