# 剧情系统设计要点

这是设计目标与约束汇总，**不是完成声明**。当前实施进度见 [IMPLEMENTATION_MATRIX.md](IMPLEMENTATION_MATRIX.md)，停止点见 [CURRENT.md](CURRENT.md)；[STATUS.md](STATUS.md)仅为历史时间线，设计差异见 [DECISIONS.md](DECISIONS.md)。主要依据为 8 月 18/23/26 日设计及 9 月 7 日计划（9 月 8 日更新）、9 月 8 日四份交接。

## 目标与范围

玩家的信件阅读、对话选择、调查、线索组合、NPC 派遣、返回报告、每日撰写真正影响后续内容。制作人员从一个 Campaign 打开 Story Workspace，编辑并引用同一批正式 DA，能查出事实来源、条件为什么满足及下一步去哪里。

分阶段推进，先有可替换的联动样例，再扩大内容。早期第一日 Truth/Conceal 双分支是验证模型的样例，不代表正式剧情文案。最新七步计划不包含完整七天正式剧本与地图美术。

## 职责划分

| 部分 | 权威职责 | 边界 |
|---|---|---|
| 内容 DA | 信件、完整对话、委托规则、线索、推论、人物资料、日期与撰写模板 | 不写入此次游玩的运行状态 |
| ContentCatalog | 显式登记正式内容；目录内 ID 唯一、引用类型正确 | 运行时不扫描目录猜测内容；编辑器扫描只产生待登记候选 |
| Campaign / Episode | 章节、入口、节点、条件、效果、转移、章节出口 | 不复制台词、图片和 NPC 资料 |
| NarrativeRuntime / FactLedger | 剧情位置、跨系统条件、事实和一次性执行记录 | 核心不依赖 Actor、Widget、World 或编辑器 |
| StoryDirector / GameplayBridge / ActionExecutor | 启动协调、玩法事件入账、动作路由与回执 | 不另存一套分支判定；具体完成语义要明确 |
| CommissionSubsystem | 草稿、派遣实例、结果评估和结算 | UI 不重新算结果；隐藏结果不能提前成为玩家已知信息 |
| ClueSubsystem | 获得日期/来源、线索与推论解锁记录 | 推论定义存在不等于已经解锁 |
| DailyWritingSubsystem | 当天草稿、可用选项、提交、封存与隐藏贡献 | 不复制其他系统的运行状态；不把撰写当新调查入口 |
| DayFlowManager | 当前日与阶段、换日事务 | 最新计划规定它唯一执行日期变化；Campaign 提供上限/内容 |
| StateTree / NPC Scene | 开场、教程、场景表现、转场、可中断活动和技术恢复 | 不与剧情图重复判断玩家选择的意义，不独立再加一次日期 |
| StoryWorldStateSubsystem | 原有标签、数值、命名结果 | 保留兼容，不自行选择 Narrative 路线 |
| UMG | 读取展示模型，调用正式操作 | 不隐藏第二套规则或直接替其他系统结算 |

## 内容组织

- `ULetterDefinition` 始终独立于委托；一封信一个资产。
- `UDialogueDefinition` 表示一次完整会话，内部保留节点、选项、条件和局部跳转；不拆成一句台词一个 DA。
- `UCommissionDefinition` 保存展示、准备限制、确定性规则、默认结果与可选表现引用。正式路径直接传 DA；旧 ID/DT 接口只作迁移兼容。
- `UClueDefinition` 描述原始事实；`UInferenceDefinition` 保存无序、不可重复的 RequiredClues 及推论内容和产出事实。正式推论不直接打开别的 UI。模型允许至少两条，现有配对交互仅处理两条，不能据此宣称多选组合可用。
- `UNPCDefinition` 保存身份、肖像和初始状态；伤势、信任、外出和活动由运行实例维护。
- `UDayDefinition` 内嵌三个撰写部分；没有复用需求时不另拆模板 DA。
- Items 是旧方案预留分类；不要只为填满内容库而新增物品系统。是否已迁移须检查最新代码。
- Campaign 是唯一制作入口，不另建 Workspace DA。Episode 保存运行时图数据，图形编辑器也编辑它，不能产生第二份图格式。

## 事实、事件与规则

- 事实键由 Type、SourceAsset、SubjectAsset、SubID 区分；值有布尔、名称、整数。事实记录保留日期、来源章节/节点及顺序号。
- 事件是一次实际发生事项；快照是已有状态。快照应在入口条件判断前入账，不重放发生奖励。
- EventID 表示同一事项，重试应保持不变；InstanceID 表示派遣/会话等真实实例；RequestID 表示一次动作请求。三者不能混用。
- 当前条件表达是“任一组满足，组内全部满足”，带比较/取反；不是已经实现任意嵌套表达式。未知/类型错误比较不因取反而成为真；判断没有获得用 NotExists。
- 普通节点转移按优先级，平级按数组顺序，默认仅在普通项不满足时使用。独立触发规则的互斥组若最高优先级并列则拒绝事件，二者规则不同。
- Repeat：EveryEvent、OncePerDay、OncePerCampaign、OncePerInstance。RunOnce 节点属于当前 Campaign 会话内成功一次；不是跨存档全局一次。
- 同一事件的规则读取“入账后、效果前”快照；单事件效果失败整批不提交。SetFact/AddIntegerFact 只修改叙事账本，不等于发物品或打开 UI。
- 独立 Triggers 不自动抢占主线、跳 NamedEntry；可选调查不能阻塞全部主线。
- 异步动作回执匹配 RequestID；相关事实先入账再选分支；失败、取消、显示失败均不能冒充成功。清理仅作用于该请求拥有的会话/Widget。
- 入口条件不满足与等待动作不同；WaitForClue 支持已有线索立即通过和未来收集后推进。

## 七日、派遣与撰写

- 没有小时/分钟消耗；挂机、阅读、调查和开关 UI 不换日。玩家主动收尾、提交撰写并睡觉才进入下一天；昼夜使用已有天气系统。
- 目标阶段：自由活动 → 请求收尾 → 夜间撰写 → 已提交待睡觉 → 换日 → 下一日/结局。未提交可取消；提交后封存当日行为与记录，过去线索页只读。
- 收尾只要求必要主线，并给出具体缺失原因；在途委托不阻止换日。
- 换日先验已提交和下一日数据，防重复，然后更新日期、到期派遣/NPC、当日内容和日开始事件，最后恢复控制。缺下一日保持原状态；第七日不能进入第八日。
- 派遣目标状态：可见 → 接取 → 准备 → 执行 → 已返回待报告 → 报告中 → 收尾。草稿可取消，确认才提交占用/交付/实例。
- 需要两次换日的委托，第一日出发第三日返回；同一日反复检查不重复推进。
- 出发快照保存资产、NPC、日期、交付数量、已告知信息、人物状态、命中规则和结果；后续编辑 DA 不改变在途结果。跨日影响必须显式配置。
- 物理返回后果与报告获知信息分开。重复报告不重复奖励。当前 Resolved 仅指旧结算成功，不能视为已听完报告。
- 交付区分消耗/归还物品、保留记录的情报、暂时不可用的实体证物。准备不足可走默认结果；无效库存、外出 NPC 等才阻止操作。
- 末日未返回应按配置保留未决事实并参与结局，不伪造返回。
- 每日恰好三个部分，各选一个；每部分恰好一个无条件默认项。其余选项由已知事实解锁；每天只提交一次。
- 可信度四档：Unformed / Doubtful / Plausible / Strong。显示印记和模糊评价，表示证据支撑程度，不保证真相正确。
- 隐藏立场 Neutral / Truthful / Cautious / Concealing / Official 及少量关键 Tag 用于结局；不直接发能力、装备等奖励。具体累计/舍入以已验证实现为准。

## NPC 与制作工具

NPC 活动按剧情/执行占用、返回报告、伤势休息、普通活动选取优先级；小地图锚点移动、停留、表演、互动。活动时间不耗日次；缺锚点和移动失败回到可诊断的等待状态。交互打断后按最新状态重新选择活动。

Story Workspace 使用 `DispatchEditor` 模块，Shipping 不依赖它。内容库通过统一接口显示各 Definition，Details 编辑专用字段；移出目录不删除资产。Narrative 页目标为图形节点/连线、条件详情、引用跳转、诊断和路线追踪；当前仍有概览部分，详见 STATUS。

隔离预览共用 `/Game/Developers/StoryPreview/L_StoryUIPreview`，使用正式 DA、Widget 和玩法子系统，仅创建临时运行状态。结束时清理请求、委托、Widget 和 PIE 状态，不写正式存档或源资产。后续可保存的是预览配置引用，不是运行中的 Preview Request；两者分开。

## 实施与验收路线

采用 9 月最新七步顺序：①数据合同 ②Campaign/事件/执行 ③派遣生命周期 ④日终/撰写/七日收尾 ⑤NPC 活动 ⑥统一编辑/迁移/预览 ⑦可替换联动样例。

步骤 7 的样例包含一委托、两 NPC、两线索与一推论、准备物、两种结果与报告、每日三部分。未调查可派遣得默认结果，调查后可改变结果；返回报告解锁撰写；真实流程和 UI 预览一致。

每阶段检查实际行为与测试。纯逻辑模拟回执不等于真实动作闭环；自动化不替代 UI 点击/焦点、NPC 移动、天气、图编辑保存撤销和预览退出的人工验收。完整游戏存档与七天正式内容是长期目标，未在最新有限交付中被证明完成。
