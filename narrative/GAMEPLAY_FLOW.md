# Dispatch Demo 完整玩法流程

更新日期：2026-09-16（Asia/Shanghai）。  
性质：面向设计者的“游戏怎样玩”总览；不记录代码完成度。

稳定要求及永久编号以 [DEMO_DESIGN.md](DEMO_DESIGN.md) 为准，实施状态以 [IMPLEMENTATION_MATRIX.md](IMPLEMENTATION_MATRIX.md) 为准。本文允许同时记录已确认、试验中和待决定的玩法方向，但必须明确标注，不能把创作方向误报为已经实现。

## 1. 核心体验

**已确认方向：** 玩家在有限信息下，通过探索、阅读、与 NPC 交谈、整理线索、选择派遣准备、等待报告和每日撰写，逐渐形成自己的判断。游戏不公开唯一正确配方，也不因玩家阅读或思考得慢而自动消耗时间。对应 `DEMO-VIS-001`、`DEMO-TIME-001`。

### 2026-10-28 玩法概念补充（待 Demo 验证）

以下内容来自用户当前构想，先作为玩法候选记录，不代表已经实现或最终定案：

- 场景可以提供查看、对话、调查、拾取、修理、交付等互动；实际保留哪些动作，以 Demo 测试后的体验为准。
- 委托目前以告示牌作为主要发现入口；入口形式和是否增加其他入口，等实际玩法验证后调整。
- NPC 可以离开场景并执行关键动作；移动、演出和返回反馈的表现方式需要在制作中调试。
- 玩家可以随时睡觉推进日期；未完成内容可能产生后果，具体后果和阻塞边界待可玩切片验证。
- 每日地图变化可以作为后续方向，包括 NPC 位置、可调查物件、地点状态、对话和环境反馈；不要求当前一次性实现全部变化。
- 普通委托也可以带来线索、NPC 变化、地图变化、物品、对话或后续入口；具体结果按实际体验调整。
- 准备不足或选择不合适的 NPC 时，倾向于返回较少或不完整的信息，让玩家无法直接知道完整剧情，而不是简单禁用派遣。
- 第一个玩法切片的重点是验证“发现问题→调查/对话→派遣→返回→报告→记录本/场景反馈”的循环，不提前锁定正式剧情。
- 素材不足时是否使用镜头、简单移动、状态切换、音效或短演出代替复杂交互，交由实际效果决定。

> **旧剧情标记（2026-10-28）**：本页的“七天”“五条核心委托”属于早期玩法/剧情草案。当前六个记录本委托只是预览数据，不代表正式剧情、数量、顺序或关联。玩法成型后，正式剧情流程、委托线和时间安排重新设计。

**试验中故事前提：** 玩家是一名被送到封闭小型区域的囚犯，原设想只有七天时间（天数待定，可能延长）；区域中发生一系列诡异事件，并出现若干委托。玩家在每天结束时写下记录，最终由某个收束阶段验收或处理记录。

## 2. 玩家从抵达到最终收束日（天数待定）

### 第一天：抵达与理解规则

**试验中。** 玩家抵达、认识区域和可接触的 NPC，理解委托、调查、派遣和记录本的基本关系。第一天承担教程职责，但不预设具体场景、人物或委托正文。

### 白天自由活动

**已确认方向。** 玩家可以：

- 阅读信件、公告、书籍、物件和环境文字；
- 与 NPC 交谈并比较不同说法；
- 获得线索，把若干线索联系成推论；
- 查看核心和关联委托；
- 选择 NPC、交付物、证物和明确告知的信息后进行派遣；
- 听取已经返回的 NPC 报告，并观察人物或区域中的后果。

阅读、探索、等待现实时间和反复打开界面不换日。玩家可以在准备不足或判断不完整时作出合法派遣选择，并承担相应结果。具体交互动作和派遣表现仍以 Demo 验证为准。

### 结束白天

**已确认方向。** 玩家主动请求结束当天。系统只检查少量必要推进条件，并明确提示未完成内容；可选调查、对话、委托和在途派遣不应全部阻止日终。

### 夜间三段撰写

**已确认方向。** 玩家根据当前真正知道和愿意表达的内容，为三个部分各选择一项记录。未提交时可以取消并返回白天；提交后当天记录封存。记录不是答案评分或能力升级，而是表达知识、判断、立场与隐瞒。

### 睡觉与换日

**已确认方向。** 玩家提交当日记录并主动睡觉后，日期才推进。换日处理到期委托、NPC 返回、新内容和下一日状态；缺少下一日数据时不得静默跳过，也不得进入不存在的下一日。对应 `DEMO-DAY-001`。

### 最终收束与验收（日期待定）

**试验中。** 原设想由第七天验收玩家形成的记录本；现在只保留“最终收束阶段”这个方向，具体日期、验收者和流程待剧情与 Demo 确定。

**待决定：** 验收者身份、验收目的、评价维度、玩家是否有机会质疑或反抗验收，以及未返回委托如何被解释。

## 3. 核心反馈循环

```text
探索、阅读与对话
  ↓
获得线索，形成或修正推论
  ↓
理解 NPC 的能力、立场、风险与隐瞒
  ↓
选择委托、NPC、交付物和明确告知的信息
  ↓
NPC 跨日执行并物理返回
  ↓
玩家听取不一定完整或可靠的报告
  ↓
人物、区域、线索和后续内容产生可辨认后果
  ↓
玩家在记录本中表达当天判断
  ↓
最终收束日根据记录与真实后果收束（具体日期待定）
```

线索解决“玩家知道什么”，派遣解决“玩家据此做什么决定”，报告提供新的但未必完整的信息，撰写记录“玩家相信什么、愿意留下什么”。四者必须互相反馈，而不是成为彼此无关的菜单。

## 4. 三种知识必须分开

| 层次 | 含义 | 玩法作用 |
|---|---|---|
| 世界真相 | 实际发生过或正在发生的事 | 保证剧本因果一致，不要求全部展示 |
| NPC 认知 | 某个 NPC 知道、误解或隐瞒的内容 | 决定对话、反应和报告可靠性 |
| 玩家认知 | 玩家已经通过真实渠道获知的内容 | 决定可用追问、派遣告知和撰写选项 |

玩家拥有线索不代表外出的 NPC 自动知道；必须在准备阶段明确告知。NPC 报告某件事也不代表它就是世界真相。

2026-10-23已确认：对话来源的信息随玩家实际听到的内容被动收集；可阅读文本来源的信息由玩家点击指定文本内容主动收集。两类都不以真假或可信程度为收集门槛；获得线索不代表认可其判断，线索匹配仍是建立联系/形成推论。未触达的对话内容不能提前发放。同一线索重复获得不重复授予。此为设计确认，不代表所有正式文本入口已实现；报告回看中的文本与已听取信息如何对应仍需明确。

## 5. 内容分类

### 五条核心委托线（旧剧情草案）

**旧草案，待重设计。** “五份奇怪的委托”曾被设为故事对玩家的核心承诺和五个剧情支柱。它不等于一份一次性任务资产，也不限制实际任务数量；当前不作为正式剧情实现依据。

### 关联委托

**试验中。** 围绕核心委托产生的前置、调查、验证、补救或后果处理内容。它们可以提供关键信息，不能因为被称为“关联”就自动视为无关紧要。

### 人物内容

**试验中。** 帮助玩家理解 NPC 的经历、能力、立场、秘密与变化。它可以采用委托、对话、信件或场景事件形式，不必全部进入派遣系统。

### 环境调查

**已确认方向。** 信件、公告、书籍、物件、环境文字与现场观察提供信息和气氛；它们可以影响推论与派遣，但不需要伪装成正式委托。

这些分类首先是创作角色。是否需要在 DataAsset 中新增正式分类字段，必须等内容案例明确后另行设计，本文不预先改变 `DATA-FOUNDATION-001`。

## 6. 派遣、返回与后果

**已确认方向。** 玩家确认派遣时锁定 NPC、准备物、已告知信息、人物状态、出发日、预计返回日和结果规则。后续修改资产或获得新线索不应改写已经发生的出发事实。

NPC 物理返回和玩家听取报告是两个阶段：返回可以先释放占用并产生伤势或状态变化；报告完成时才把其中信息写入玩家知识。重复查看不得重复发放线索、物品或结果。

报告首次听取由返回的对应 NPC 对话发起；记录本在进行中分类内显示“待听报告”过渡提示，标签可打开进行中页面查看已知信息，但不从记录本开始首次报告或直接结算。报告完成后的只读回看仍是后续方向，须访问同一委托实例并避免重复授予；具体交互与视觉见 [委托返回与报告入口](ui/COMMISSION_REPORT_UI.md)。

重要结果应重新进入玩家所在的小区域，例如人物状态、新对话、信件、物件、线索或其他 NPC 反应；不是只有一行“成功/失败”。

2026-10-23已确认：派遣报告与NPC对话是获得线索的另一渠道，核心收益是信息，实物不是必需奖励。实际对话中获得的相关描述自动进入线索栏；例如鹿角本体可以没有背包用途，关于鹿角的描述可作为线索。若确实交付实物，则随对话交给玩家进入背包，不要求在报告页另行点击领取。允许只获得线索而不新增背包物品；不因此删除其他物品用途或把所有物品自动转为线索。信息真假仍不影响收集，同一线索重复查看不重复授予。

## 7. 非理想路径也必须能继续

- 不调查：仍可派遣并得到默认或信息不足的结果。
- 判断错误：产生能够理解的后果，而不是把按钮禁用。
- 准备不足：只要不存在真实操作冲突，可以确认派遣。
- 选择不合适的 NPC：体现人物差异、风险和立场，不依赖公开成功率。
- 没听报告：NPC 可以已经返回，但玩家仍未获得报告中的知识。
- 委托来不及返回：按数据拒绝出发或作为未决事项进入结局，不能静默消失。
- 可选内容未完成：允许进入日终和结局，并成为玩家选择的一部分。

## 8. 自由推进、默认撰写与结局输入

**试验中方向：** 玩家每天做什么由玩家决定。委托、线索、对话、物品和报告不作为必须完成的通关清单；玩家可以完全不做委托，甚至连续多日不参与已开放内容，仍然能够结束一天、提交撰写并进入结局。

每天三个撰写部分始终提供无条件默认项。默认项不能只是开发占位文字，而应能表达沉默、敷衍、服从、无法判断、拒绝表态或其他与当日缺少信息相符的状态。玩家完成调查后可以获得新的表达选项，但即使知道更多，也可以选择不写或继续采用较保守的内容。

每日撰写目前只有早期 UI 概念，没有正式完成的 Widget。概念图可保留逐步回填、全文预览、封存仪式和可信度印记等表现方向，但其中的五步流程不能直接替代当前固定三部分的数据合同；见 [每日撰写 UI 概念](ui/DAILY_WRITING_UI.md)。

**试验中结局边界：** 撰写是结局的重要参考，但不是唯一输入。结局还可以读取实际人物状态、地图或世界变化、关键决定、已发生/未决委托和其他长期事实。记录本主要表达玩家如何理解和呈现多日经历；世界不会因为某件事没有写入记录本就被当作从未发生。

这套方向目前不自动替代 [DEMO_DESIGN.md](DEMO_DESIGN.md) 中“日终检查少量必要推进条件”的旧表述。进入实现前需要用可玩切片验证：是否真的可以移除全部内容门槛，还是只保留教程、转场和技术完整性所需的最低条件。

## 9. 多日体验递增与每日世界变化（天数待定）

**体验目标，尚未形成正式内容排程：** 多日流程不应把同一套可预测任务重复执行。底层循环可以稳定，但文本剧情、NPC 反馈、地图、物品、事件和可用功能应有机会随日期及玩家过去的行为发生变化，使玩家不能在开始阶段就完整看穿后续体验。

候选变化来源包括：

- 文本和剧情逐渐揭示新问题，旧信息产生矛盾或新的解释；
- NPC 因派遣、伤势、关系、秘密、缺席或返回报告改变状态和反馈；
- 地图开放新区域，或旧区域出现新的物件、人物与环境变化；
- 特殊物品触发事件，物品按日期刷新或进入不同阶段；
- 商人在特定日期出现，推动剧情、提供特殊物品并消耗金币；
- 后续日期开放新的玩法区块或功能；
- 早期行为产生延迟反馈，并与后期内容交叉。

以上均为候选手段，不是固定天数必须全部采用的功能清单。每天也不需要强行增加一个永久系统；新内容、旧内容反转和早期选择的后果都可以形成递增。即使玩家什么都不做，日期本身仍可以推动少量作者设定的世界变化，但不能因此伪造玩家没有做过的行为。

推荐的待验证结构是：每天存在少量与日期相关的基础变化，再叠加由玩家选择触发的条件变化。它能否形成足够惊喜、是否造成错过压力、哪些变化值得正式实现，都必须通过实际可玩内容判断。

## 10. 迭代验证而非提前设计完整多日流程

**当前先行阶段：先完成脱离地图也能验证的 UI 基础功能链。** 当前不直接编排 Day 1，也不先设计教程、地图中的具体触发位置或完整 NPC 行为。先使用可替换的测试内容，使以下界面与状态变化能够连续操作：

```text
获得线索
→ 接取委托
→ 打开记录本并切换委托、物品、线索三页
→ 选择两条线索并得到成功或失败反馈
→ 进入派遣并完成基本选择/确认
→ 进入每日撰写并完成基本选择/提交
```

本阶段所说的“完成 UI 基本功能”至少要求入口、返回、页面切换、选择、确认、失败反馈及必要状态刷新能连贯工作；它不代表最终视觉、美术动画、正式文本或完整玩法体验已经完成。可以使用现有调试/隔离预览入口验证，但预览不能替代以后在地图中的实际操作验收。

UI 功能链稳定后，下一阶段才把它放回地图，实际测试玩家怎样发现入口、怎样侧身/观察/交互、不同模块怎样衔接，以及玩家是否知道下一步能做什么。Day 1 的内容编排、教程触发与锁定、NPC 动作反馈、节奏和体验打磨在地图测试后继续设计，不能反过来阻塞当前 UI 基本功能。

编辑设计流程随 UI 功能链逐步改进：当前只要求相应测试内容可配置、可预览、错误可定位；不提前建设覆盖全部七日、完整 NPC 行为或最终剧情制作的庞大编辑器。

**后续制作方法：** 不要求在制作前把正式剧本、商人、地图变化、物品事件、新功能和结局全部设计完美。新想法先作为候选；只有在最小可玩版本中产生明确价值，才升级为稳定要求。

建议下一次玩法验证使用一个可替换的 2～3 日纵向切片，最少覆盖：

- 什么都不做也能使用默认撰写并正常换日；
- 调查后能获得不同信息或撰写选项；
- 一次 NPC/委托选择在后续日期产生报告或可见反馈；
- 至少一种与日期相关的世界变化；
- 撰写与实际世界状态共同影响一个临时收束结果。

这个切片不需要旧草案中的五条委托、完整世界真相、多日正文、商人、新地图和多个新功能同时存在。体验后分别判断保留、修改或删除，再决定下一批设计。当前 `DATA-FOUNDATION-001` 的样例主要证明数据可编辑、可引用和可预览，不等于这套完整循环已经好玩。

## 11. 玩法与故事怎样互相约束

玩法文档规定玩家能够采取哪些行动、获得什么反馈；[Story Bible](story/STORY_BIBLE.md) 规定这些行动发生在什么人物、真相和剧情背景下。新增故事内容必须能通过现有或明确新增的玩法渠道被玩家接触；新增玩法必须说明它怎样增强核心判断循环，而不能只增加操作数量。

具体对话、信件、委托描述、报告、线索、撰写和结局文本进入 [Text Index](story/TEXT_INDEX.md)，确认后再按独立授权录入正式 DataAsset。

## 12. 当前待决定的玩法问题

- 正式委托线的数量、关系和节奏；旧草案的五条核心线不再视为定案。
- 关联委托通过什么条件出现，是否占用 NPC 的派遣时间。
- 三个 NPC 是否为最终数量，以及他们分别承担哪些互补判断维度。
- 最终收束阶段验收事实准确度、记录立场、服从程度，还是验收者隐藏目的。
- 教程和收尾之外，中间需要多少天才能容纳核心与可选内容。
- 什么构成最短可通关路径，哪些调查属于可选但有意义的重玩内容。
- 玩家完全误判、拒绝部分委托或多个委托未决时，结局怎样仍然成立。
